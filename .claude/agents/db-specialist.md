# Правила схем

- `@Schema({ timestamps: true })` у всех коллекций.
- Деньги — **integer в центах** (`priceCents`), никогда float.
- Обязательные поля — `required: true`; enum-поля — `enum` в схеме.
- Связи — `Types.ObjectId` + `ref`. `populate` только там, где реально нужно.
- **Снапшоты в заказах:** в `orders.items` храни `name`, `priceCents`, `quantity` на момент
  покупки — цена товара потом может измениться. Объясняй такие решения.
- Чувствительные поля (`passwordHash`) — `select: false`.
- Массивы, которые растут бесконечно (сообщения чата), — ограничивай или выноси в отдельную
  коллекцию. Помни про лимит документа 16 MB.
- `aiLogs` — TTL-индекс (например, 90 дней), чтобы коллекция не росла вечно.
- `chatSessions.pendingAction` — с полем `expiresAt`.

# Индексы

- Каждый индекс обоснован конкретным запросом. В комментарии над индексом пиши, какой запрос он ускоряет.
- Типичные:
  - `products`: `{ category: 1, priceCents: 1 }`, текстовый индекс `{ name: 'text', description: 'text', tags: 'text' }`,
    `{ slug: 1 }` unique;
  - `orders`: `{ userId: 1, createdAt: -1 }`;
  - `carts`: `{ userId: 1 }` unique;
  - `chatSessions`: `{ userId: 1, updatedAt: -1 }`;
  - `aiLogs`: `{ createdAt: 1 }` TTL, `{ agent: 1, createdAt: -1 }`.
- Составной индекс — порядок полей по правилу **ESR**: Equality → Sort → Range. Объясняй его.
- Проверяй запросы через `.explain('executionStats')`: нет ли `COLLSCAN` на больших коллекциях.

---

# Агрегации

- Пиши пайплайны как типизированные методы с понятным именем:
  `getSalesStats({ from, to, groupBy })`, `getLowStockProducts({ threshold, limit })`.
- `$match` — как можно раньше (использует индексы и уменьшает объём).
- Всегда `$limit` для результатов, которые пойдут в AI-агента (компактный ответ, ~10 строк).
- Над каждым этапом пайплайна — короткий комментарий, что он делает.
- Результат — только нужные поля (`$project`).

# Сид-данные (`backend/scripts/seed.ts`)

- 40–60 реалистичных товаров в 5–7 категориях: название, описание, теги, цена,
  остаток, картинка (placeholder URL), рейтинг.
- Разнообразие для AI-тестов: разные цены (5€–300€), товары «для спорта», «подарок»,
  «для дома», несколько товаров с низким остатком.
- 2 пользователя: `user@test.com` и `admin@test.com` (пароли из `.env.example`, хешированные).
- Несколько заказов с разными статусами для Support-агента.
- Скрипт **идемпотентный**: повторный запуск не дублирует данные (очистка или upsert).
- Запуск: `npm run seed`. Никогда не запускать против production-базы — проверка env.

# Vector Search (бонус-этап)

- Только когда разработчик попросит.
- Поле `embedding: number[]` в `products`, индекс Atlas Vector Search (создаётся в Atlas или через скрипт).
- Запрос через `$vectorSearch` с фильтром по категории/цене.
- Объясни разницу между текстовым и векторным поиском.
