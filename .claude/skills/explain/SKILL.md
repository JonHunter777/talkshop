# Объяснение кода для junior

Аргумент: `$ARGUMENTS` — путь к файлу или папке, имя функции/класса или понятие.

Примеры:
- `/explain backend/src/ai/agent-runner.service.ts`
- `/explain ProductsService.search`
- `/explain backend/src/auth`
- `/explain prompt caching`

Разработчик — junior-верстальщик, который растёт до fullstack / AI web developer.
HTML, CSS и базовый JavaScript он знает. NestJS, MongoDB, TypeScript-дженерики,
DI и AI-агенты — новые для него темы.

Этот скилл **только объясняет**. Ничего не меняй в коде.

---

## Шаг 1. Собрать контекст

1. Найди и прочитай указанный код целиком.
2. Найди, **кто его вызывает** и **что он вызывает** (`Grep`) — чтобы показать место в проекте.
3. Если это понятие (а не файл) — найди, где оно используется в этом проекте, и объясняй на этом коде.
4. Если аргумент не найден — покажи похожие варианты и спроси, что имелось в виду.

---

## Шаг 2. Объяснение

Пиши **на русском, простыми словами**. Короткие предложения.
Термин — сначала простое объяснение, потом название (а не наоборот).

### Структура ответа

**1. Одной фразой**
Что это и зачем нужно в магазине. Без терминов.

**2. Аналогия из жизни**
Одна короткая аналогия (кассир, склад, официант и т.п.), если она реально помогает.

**3. Место в проекте**
Кто вызывает → этот код → что вызывает он:
```
React (CartPage) → POST /cart/items → CartController → CartService → MongoDB (carts)
```

**4. Разбор по шагам**
Пройди по коду сверху вниз. Для больших файлов — только ключевые части.
Показывай короткие фрагменты (до ~15 строк) и объясняй:
- **что** делает этот кусок;
- **почему** написано так (связь с правилами проекта: безопасность, цены в центах, userId из JWT…).

**5. Новые понятия**
2–5 понятий из кода (DI, декоратор, DTO, `lean()`, guard, tool use, SSE…).
Для каждого — 1–2 предложения и где ещё оно встречается в проекте.

**6. Частые ошибки**
2–3 ошибки, которые новички делают с таким кодом, и чем они опасны.

**7. Проверь себя**
3 вопроса, которые могут задать **на собеседовании** по этой теме. Ответы — под спойлером:
```
<details><summary>Ответ</summary>
...
</details>
```

**8. Попробуй сам** (по желанию)
Одно маленькое упражнение на 10–20 минут по этому коду
(например: «добавь фильтр по рейтингу в query DTO»). Без готового решения.

---

## Правила

- Объём: для файла — коротко и по делу; для папки или модуля — обзор + самые важные места.
- Не пересказывай очевидное (`import`, геттеры), фокусируйся на сложном.
- Связывай с тем, что разработчик уже знает: HTML-формы, `fetch`, DOM-события, CSS.
- Если в коде есть проблема — упомяни коротко в конце («💡 Заметил: …») и предложи
  передать `code-reviewer`. Не исправляй.
- Не выдумывай: если не уверен, как работает библиотечная функция, так и скажи.
