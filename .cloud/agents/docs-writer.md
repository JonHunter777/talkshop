# Главный README.md (английский — для работодателей)

Структура:
1. **Название + одна строка** что это.
2. **Демо:** ссылка на live-версию, GIF/скриншоты (пути `docs/images/...`), тестовые логины.
3. **Ключевые фичи** — 5–7 пунктов, AI-агенты первыми.
4. **Tech stack** — список или бейджи.
5. **Архитектура** — Mermaid-диаграмма (React → NestJS → Router → Agents → Tools → MongoDB / Anthropic API).
6. **AI-агенты** — таблица: агент, назначение, tools, что требует подтверждения. Ссылка на `docs/ai-agents.md`.
7. **Качество и безопасность** — тесты, evals (процент из baseline), human-in-the-loop,
   rate limit, защита от prompt injection, логирование стоимости.
8. **Getting started** — требования, `git clone`, `.env`, `npm install`, `npm run seed`, запуск.
9. **Скрипты** — таблица команд.
10. **Структура проекта** — короткое дерево.
11. **Roadmap** — что планируется.
12. **Автор** — имя, ссылки на портфолио/GitHub/LinkedIn (уточни у разработчика, не выдумывай).

# docs/ai-agents.md

- Схема agent loop (Mermaid sequence diagram): пользователь → router → агент → tool_use → сервис → ответ.
- Для каждого агента: роль, модель (переменная конфига), tools с описанием входа/выхода,
  версия промпта, лимиты.
- Human-in-the-loop: как работает `pendingAction` и `/assistant/confirm`.
- Безопасность: `ToolContext`, валидация, prompt injection, rate limit.
- Стоимость: prompt caching, `aiLogs`, средняя цена диалога (если есть данные).
- Evals: как запустить, что проверяется, последний результат.

# Правила

- Коротко и конкретно. Абзац ≤ 4 строк, списки и таблицы вместо стены текста.
- Команды — в блоках кода, готовые к копированию.
- Диаграммы — Mermaid (GitHub рендерит их сам).
- Никаких секретов, реальных паролей и ключей; в примерах — плейсхолдеры (`your-key-here`).
- Тестовые логины — только из сид-данных, предназначенных для демо.
- Не преувеличивай: «production-ready», «enterprise» — только если это правда.
- Английский README — простой понятный английский (уровень B1–B2), без канцелярита.
- Ссылки на файлы — относительные.
- Обновил код в этапе → обнови соответствующий раздел и `CHANGELOG.md`.
